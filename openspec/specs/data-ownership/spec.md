# data-ownership Specification

## Purpose

Делает так, чтобы у каждого пользователя были свои контакты, заметки и группы: он видит и меняет только их, а чужие для него как будто не существуют - ни на экранах, ни в прямых запросах к серверу.

## Requirements

### Requirement: У каждой записи есть владелец
У каждого контакта и каждой группы SHALL быть владелец - пользователь, который их создал. Заметки принадлежат владельцу контакта. Связь «контакт - группа» бывает только между контактом и группой одного владельца.

#### Scenario: Новый контакт
- **GIVEN** пользователь вошёл как anna@example.com
- **WHEN** он добавляет контакт «Вера» с заметкой и группой «Теннис»
- **THEN** контакт, его заметка и группа «Теннис» принадлежат anna@example.com

### Requirement: Пользователь видит только своё
Каждый экран SHALL показывать только записи вошедшего пользователя: список контактов и счётчик «Всего N контактов», поиск, карточку и заметки, страницу «Группы» и число контактов в группах, группы в карточке, в форме и в фильтре, блок «Пора связаться».

#### Scenario: Критерий успеха - два пользователя
- **GIVEN** A вошёл по ссылке и добавил контакт «Вера Автотестова»
- **WHEN** B входит по ссылке под своей почтой
- **THEN** контакта «Вера Автотестова» нет в списке B и не находится поиском
- **AND** по прямой ссылке на этот контакт B видит «Такого контакта нет»

#### Scenario: Счётчик и поиск
- **GIVEN** у A 3 контакта, у B - 1 контакт «Вера»
- **WHEN** B открывает главную и ищет «Вера»
- **THEN** у B «Всего 1 контакт», поиск находит только его «Веру»

#### Scenario: Пора связаться
- **GIVEN** у A есть контакт, с которым пора связаться
- **WHEN** B открывает главную
- **THEN** в блоке «Пора связаться» у B нет контакта A

#### Scenario: Группы
- **GIVEN** у A есть группа «Теннис» с 2 контактами
- **WHEN** B открывает страницу «Группы», фильтр на главной и список групп в своей карточке контакта
- **THEN** группы «Теннис» пользователя A нигде нет

#### Scenario: Чужая группа в адресе
- **GIVEN** B открыл главную с фильтром по группе A в адресе страницы
- **WHEN** страница загрузилась
- **THEN** у B выбраны «Все группы» и виден весь его список - так же, как для удалённой группы

### Requirement: Чужой контакт как несуществующий
Чужой контакт по прямой ссылке SHALL выглядеть так же, как контакт, которого нет: страница «Такого контакта нет» с кнопкой «К списку контактов». По ней нельзя понять, что такой контакт есть у кого-то другого.

#### Scenario: Прямая ссылка на чужой контакт
- **GIVEN** у A есть контакт «Вера»
- **WHEN** B открывает адрес карточки «Веры»
- **THEN** видно «Такого контакта нет» - та же страница, что для удалённого контакта, без имени, заметок и групп «Веры»

### Requirement: Чужое нельзя изменить прямым запросом
Сервер SHALL проверять владельца при каждом изменении, а не полагаться на то, что кнопки чужих записей не видны. Запрос с номером чужой записи получает тот же ответ, что запрос с номером несуществующей: «Контакт не найден — возможно, его уже нет в базе.» или «Группа не найдена — возможно, её уже удалили.». Чужие данные при этом не меняются.

#### Scenario: Чужой контакт
- **GIVEN** у A есть контакт «Вера» с заметками
- **WHEN** B прямым запросом к серверу пытается изменить или удалить «Веру», сменить её частоту общения, добавить ей заметку, отметить «Связались» или отменить «Связались»
- **THEN** B получает «Контакт не найден — возможно, его уже нет в базе.», «Вера» и её заметки у A не изменились

#### Scenario: Чужая группа
- **GIVEN** у A есть группа «Теннис»
- **WHEN** B прямым запросом пытается переименовать или удалить «Теннис»
- **THEN** B получает «Группа не найдена — возможно, её уже удалили.», группа A не изменилась

#### Scenario: Свой контакт в чужую группу
- **GIVEN** у A есть группа «Теннис», у B - контакт «Олег»
- **WHEN** B прямым запросом пытается добавить «Олега» в «Теннис» A
- **THEN** B получает «Группа не найдена — возможно, её уже удалили.», в группе A никого не прибавилось

#### Scenario: Чужой контакт в свою группу
- **GIVEN** у A есть контакт «Вера», у B - группа «Друзья»
- **WHEN** B прямым запросом пытается добавить «Веру» в свою группу или создать для неё группу
- **THEN** B получает «Контакт не найден — возможно, его уже нет в базе.», «Вера» ни в одну группу B не попала, новой группы у B не появилось

#### Scenario: Чужая группа в форме контакта
- **GIVEN** у A есть группа «Теннис»
- **WHEN** B прямым запросом сохраняет свой контакт и указывает в нём группу «Теннис» A
- **THEN** контакт B сохраняется без этой группы - так же, как с группой, которую удалили, - в группе A никого не прибавилось

### Requirement: Начало нового пользователя
Новый пользователь SHALL начинать с пустого списка: «Всего 0 контактов», надпись «Пока нет ни одного контакта» и подсказка «Нажмите «Добавить контакт», чтобы записать первого человека.». Блока «Пора связаться» нет. Готовые группы нового пользователя - в `contact-groups`.

#### Scenario: Первый вход
- **GIVEN** под boris@example.com ни разу не входили, а у других пользователей есть контакты
- **WHEN** Борис входит по ссылке впервые
- **THEN** он видит «Всего 0 контактов», «Пока нет ни одного контакта» и подсказку «Нажмите «Добавить контакт», чтобы записать первого человека.»

### Requirement: Уже существующие данные - владельцу
При обновлении приложения до версии со входом все контакты, заметки и группы, которые уже есть в базе, SHALL стать данными владельца - пользователя с почтой из настройки `OWNER_EMAIL`. Ни одна запись не теряется и не меняется, кроме того, что у неё появляется владелец. Если данные есть, а `OWNER_EMAIL` не указан или указан неверно, обновление базы останавливается, ничего не меняя, и продолжает работать прошлая версия.

#### Scenario: После обновления
- **GIVEN** до обновления в базе N контактов, M заметок, K групп и L связей «контакт - группа»
- **WHEN** приложение обновилось до версии со входом
- **THEN** контактов, заметок, групп и связей по-прежнему N, M, K и L, у каждой записи прежние данные, и все они принадлежат пользователю с почтой из `OWNER_EMAIL`

#### Scenario: Владелец входит
- **GIVEN** приложение обновилось до версии со входом
- **WHEN** владелец входит по ссылке под почтой из `OWNER_EMAIL`, написанной в любом регистре
- **THEN** он видит все прежние контакты, их заметки, группы и блок «Пора связаться» - как до обновления

#### Scenario: Почта владельца не указана
- **GIVEN** в базе есть контакты или группы, а `OWNER_EMAIL` в настройках нет или в нём не адрес почты
- **WHEN** выкатка применяет обновление базы
- **THEN** обновление базы останавливается с понятной ошибкой, данные не изменились, новая версия не запускается

### Requirement: Демо-данные у владельца
Тестовые данные (`pnpm db:seed`) SHALL создаваться у пользователя с почтой из `OWNER_EMAIL`. У других пользователей демо-данных нет.

#### Scenario: Заполнить пустую базу
- **GIVEN** база пустая
- **WHEN** выполняется `pnpm db:seed`, затем владелец входит под почтой из `OWNER_EMAIL`
- **THEN** он видит «Всего 1 000 контактов» с заметками и группами
- **AND** другой пользователь после входа видит пустой список
