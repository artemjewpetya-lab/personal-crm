# Личная CRM

Приложение, где хранятся контакты людей, которых вы знаете лично: кто это, откуда знакомы, телефон, почта и заметки о том, о чём договорились.

Идея и критерии успеха — в `specs/01-продуктовая-идея.md`.

## Что умеет

- Список всех контактов по алфавиту и счётчик «Всего N контактов».
- Поиск по имени, почте или телефону (буквы «е» и «ё» считаются одинаковыми: «Артем» найдёт «Артём»).
- Добавление контакта: обязательно только имя, остальное — по желанию.
- Карточка контакта: все данные, кнопка «Изменить» и заметки. Новая заметка сохраняется кнопкой «Добавить заметку» или сочетанием Ctrl + Enter.
- Данные хранятся в базе PostgreSQL, поэтому в любом браузере на этом компьютере видно одно и то же.

Приложение открывается только на этом компьютере (адрес `http://localhost:3000`) — входа по паролю нет, поэтому в сеть оно специально не выставлено.

## Что нужно установить

- Docker Desktop — в нём работает база данных.
- Node.js 24 и pnpm.

## Первый запуск

Все команды выполняются в папке проекта `Personal CRM` — там, где лежит файл `package.json`. Если запустить команду в другой папке, pnpm ответит ошибкой `Command "dev" not found`.

1. Если файла `.env` ещё нет — скопируйте `.env.example` в `.env` и заполните значения.
2. Запустите базу данных (нужен запущенный Docker Desktop):

   ```
   docker compose up -d
   ```

3. Установите зависимости:

   ```
   pnpm install
   ```

4. Создайте таблицы в базе:

   ```
   pnpm db:migrate
   ```

5. Заполните базу тестовыми данными — 1000 контактов с заметками:

   ```
   pnpm db:seed
   ```

   Команда безопасна: если в базе уже есть хотя бы один контакт, она ничего не делает.

6. Соберите и запустите приложение:

   ```
   pnpm build
   pnpm start
   ```

7. Откройте в браузере `http://localhost:3000`.

Остановить приложение — `Ctrl + C` в окне, где оно запущено.

## Повседневный запуск

```
docker compose up -d
pnpm start
```

Если вы меняли код — перед `pnpm start` выполните `pnpm build`.

Для разработки удобнее `pnpm dev`: изменения в коде видны сразу, без пересборки.

## Как проверить руками

1. Откройте `http://localhost:3000` — виден список контактов и надпись «Всего 1 000 контактов».
2. Нажмите «Добавить контакт», впишите имя (например, «Тест Тестов») и нажмите «Добавить». Список прокрутится к новому контакту и подсветит его, сверху появится сообщение «Контакт добавлен».
3. Наберите в поиске «Тест Тестов» — останется один контакт. Нажмите на него — откроется карточка.
4. Напишите заметку и нажмите «Добавить заметку» — она появится под полем. Обновите страницу (F5) — заметка на месте.
5. Скопируйте адрес карточки и откройте его в другом браузере (например, в Chrome, если работали в Edge) — там тот же контакт и та же заметка.

## База данных (PostgreSQL в Docker)

Проверить, что база работает:

```
docker compose ps
```

В колонке `STATUS` у `db` должно быть `healthy`.

Остановить базу: `docker compose stop`. Данные хранятся в томе Docker `personal-crm_pgdata` и при остановке не пропадают.

Данные лежат в Docker, а не в папке проекта. Имя `personal-crm` закреплено в `compose.yaml` (строка `name: personal-crm`), поэтому папку проекта можно переносить и переименовывать — база останется той же. Эту строку не меняйте: иначе Docker создаст новую пустую базу, а контакты останутся в старой.

Удалить базу вместе со всеми данными: `docker compose down -v` — это необратимо.

Приложение подключается к базе по строке `DATABASE_URL` из `.env`.

## Все команды

| Команда | Что делает |
| --- | --- |
| `pnpm dev` | Запуск в режиме разработки |
| `pnpm build` | Сборка приложения |
| `pnpm start` | Запуск собранного приложения |
| `pnpm db:migrate` | Применяет к базе изменения структуры таблиц (миграции из папки `drizzle`) |
| `pnpm db:generate` | Создаёт новую миграцию после изменения схемы в `src/db/schema.ts` |
| `pnpm db:seed` | Заполняет пустую базу 1000 тестовыми контактами |
| `pnpm test:e2e` | Автоматически проходит главный сценарий в Edge и Chrome (см. ниже) |
| `pnpm lint`, `pnpm typecheck` | Проверки кода |

## Автоматическая проверка сценария

`pnpm test:e2e` открывает приложение в Edge, добавляет контакт, находит его, пишет заметку, обновляет страницу, а потом открывает тот же адрес в Chrome и сверяет данные. Используются браузеры, уже установленные на компьютере, — в отдельном временном профиле, ваши вкладки и данные не затрагиваются. Созданный тестом контакт в конце удаляется из базы. Если приложение не запущено, тест сам запустит `pnpm dev`.

## Про символ «#» в пути к папке

Раньше проект лежал в папке `# Онлайн курсы`, а символ `#` в пути мешает некоторым инструментам. Сейчас папка называется `00 Онлайн курсы`, и проблем нет. Если когда-нибудь снова положить проект в папку с `#` в названии:

- Tailwind CSS (оформление интерфейса) по-прежнему соберётся: на этот случай оставлен патч `patches/@tailwindcss__node@4.3.3.patch`, он применяется автоматически при `pnpm install` и в обычной папке ни на что не влияет. При обновлении Tailwind патч, возможно, придётся обновить или убрать.
- В режиме `pnpm dev` в окне сервера может появляться ошибка `Could not validate instant ... Could not find the module ... in the React Client Manifest`. Это сбой внутренней проверки Next.js из-за `#`, на работу приложения он не влияет, а в `pnpm start` его нет.
