# Личная CRM

Приложение, где хранятся контакты людей, которых вы знаете лично: кто это, откуда знакомы, телефон, почта и заметки о том, о чём договорились.

Идея и критерии успеха — в `specs/01-продуктовая-идея.md`.

## Что умеет

- Список всех контактов по алфавиту и счётчик «Всего N контактов».
- Поиск по имени, почте или телефону (буквы «е» и «ё» считаются одинаковыми: «Артем» найдёт «Артём»).
- Добавление контакта: обязательно только имя, остальное — по желанию.
- Карточка контакта: все данные, кнопка «Изменить» и заметки. Новая заметка сохраняется кнопкой «Добавить заметку» или сочетанием Ctrl + Enter.
- Частота общения: в форме контакта поле «Как часто общаться» — раз в неделю, месяц, квартал, год или «Не задано» (по умолчанию). Выбранная частота видна в карточке: «Общаемся раз в месяц». Эта надпись — кнопка: по нажатию открывается список частот, выбор сохраняется сразу, без формы. Без частоты на этом месте кнопка «Задать частоту».
- Блок «Пора связаться» над списком контактов: люди, с которыми срок уже прошёл, самые просроченные сверху. Срок считается от последней заметки, а если заметок нет — от момента, когда задали частоту. В строке — сколько дней просрочено, дата последней заметки и её начало; сразу видно 5 человек, остальных раскрывает «Показать всех (N)». Пока идёт поиск, блок скрыт.
- Кнопка «Связались» — в строке блока и в карточке контакта с заданной частотой: сохраняет заметку «Связались», срок начинается заново, контакт уходит из блока. Обычная заметка действует так же. Нажали по ошибке — в сообщении о сохранении 10 секунд есть кнопка «Отменить»: заметка удаляется, всё как было.
- Группы: «Семья», «Друзья», «Коллеги» есть сразу, свои создаёте сами («Теннис», «Аналитики»). Контакт может быть в нескольких группах или ни в одной. Название группы не повторяется: «Теннис» и «теннис», «Елка» и «Ёлка» — одно и то же.
- Группы в карточке контакта: рядом с частотой общения видны группы человека или кнопка «Добавить в группу». Нажатие открывает список всех групп с отметками: отметили — сохранилось сразу, без формы. Здесь же можно вписать название и выбрать «Создать группу «…»».
- Группы в форме «Добавить контакт» и «Изменить»: поле «Группы» последним. Выбираете группы, убираете лишние, создаёте новую; всё сохраняется вместе с формой. Закрыли форму без сохранения — ничего не изменилось, в том числе новая группа не создалась.
- Группы на главной: под именем в общем списке видны группы человека. Рядом с поиском — выбор группы («Все группы» по умолчанию): в списке остаются только её люди, счётчик «Найдено: N контактов из M». Фильтр работает вместе с поиском и записан в адресе страницы, поэтому переживает F5 и открывается в другом браузере. Блок «Пора связаться» фильтр не затрагивает.
- Страница «Группы» (кнопка на главной): все группы по алфавиту и число контактов в каждой; название открывает главную с фильтром по этой группе. Здесь группу создают, переименовывают и удаляют; при удалении люди остаются, пропадает только группа.
- Данные хранятся в базе PostgreSQL, поэтому в любом браузере на этом компьютере видно одно и то же.

Локально приложение открывается только на этом компьютере (адрес `http://localhost:3000`). Версия на сервере — https://app.personalcrm.site (см. «Выкатка на сервер»). Входа по паролю нет, и адрес на сервере открыт всем, кто его знает, поэтому там только тестовые данные — настоящие контакты туда не вносите.

## Что нужно установить

- Docker Desktop — в нём работает база данных.
- Node.js 24 и pnpm.
- OpenSpec — нужен только для работы над новыми фичами (см. «Требования к фичам: OpenSpec»): `npm install -g @fission-ai/openspec@latest`.

## Первый запуск

Все команды выполняются в папке проекта `Personal CRM` — там, где лежит файл `package.json`. Если запустить команду в другой папке, pnpm ответит ошибкой `Command "dev" not found`.

1. Если файла `.env` ещё нет — скопируйте `.env.example` в `.env` и заполните значения.
2. Запустите базу данных (нужен запущенный Docker Desktop):

   ```
   docker compose up -d
   ```

3. Установите зависимости:

   ```
   pnpm install
   ```

4. Создайте таблицы в базе:

   ```
   pnpm db:migrate
   ```

5. Заполните базу тестовыми данными — 1000 контактов с заметками, примерно у 15% из них задана частота общения (поэтому блок «Пора связаться» сразу не пустой), а часть разложена по готовым группам — около 3% в «Семье», 10% в «Друзьях», 20% в «Коллегах», некоторые сразу в двух:

   ```
   pnpm db:seed
   ```

   Команда безопасна: если в базе уже есть хотя бы один контакт, она ничего не делает.

6. Соберите и запустите приложение:

   ```
   pnpm build
   pnpm start
   ```

7. Откройте в браузере `http://localhost:3000`.

Остановить приложение — `Ctrl + C` в окне, где оно запущено.

## Повседневный запуск

```
docker compose up -d
pnpm start
```

Если вы меняли код — перед `pnpm start` выполните `pnpm build`.

Для разработки удобнее `pnpm dev`: изменения в коде видны сразу, без пересборки.

## Как проверить руками

1. Откройте `http://localhost:3000` — виден список контактов и надпись «Всего 1 000 контактов».
2. Нажмите «Добавить контакт», впишите имя (например, «Тест Тестов») и нажмите «Добавить». Список прокрутится к новому контакту и подсветит его, сверху появится сообщение «Контакт добавлен».
3. Наберите в поиске «Тест Тестов» — останется один контакт. Нажмите на него — откроется карточка.
4. Напишите заметку и нажмите «Добавить заметку» — она появится под полем. Обновите страницу (F5) — заметка на месте.
5. Скопируйте адрес карточки и откройте его в другом браузере (например, в Chrome, если работали в Edge) — там тот же контакт и та же заметка.

Частота общения и «Пора связаться». Если база заполнялась до появления частоты, ни у кого её ещё нет и блока «Пора связаться» на главной нет — начните с шага 6. На свежей базе после `pnpm db:seed` блок виден сразу.

6. Откройте карточку контакта, у которого последняя заметка написана больше недели назад. Под «Кто это» — кнопка «Задать частоту». Нажмите её и выберите «Раз в неделю»: кнопка станет надписью «Общаемся раз в неделю», рядом появится «Связались». То же можно сделать через «Изменить» → поле «Как часто общаться».
7. Нажмите «Все контакты» — над списком появился блок «Пора связаться», в нём этот контакт: «Просрочено на N дней (последняя заметка …)» и начало заметки. Сам контакт остался и в общем списке на своём месте.
8. Нажмите на строку контакта в блоке (не на кнопку) — откроется его карточка. Вернитесь на главную.
9. Наберите что-нибудь в поиске — блок пропадёт. Очистите поиск — блок снова на месте.
10. Нажмите «Связались» в строке контакта — появится сообщение «Заметка «Связались» сохранена» с кнопкой «Отменить», контакт исчезнет из блока, а вы останетесь на главной. Нажмите «Отменить» (пока сообщение видно, 10 секунд) — контакт вернётся в блок на своё место.
11. Снова нажмите «Связались» и подождите 10 секунд — сообщение пропадёт, отменить уже нельзя. Откройте карточку — сверху заметок новая заметка «Связались» с текущим временем.
12. В карточке нажмите «Общаемся раз в неделю» и выберите «Не задано» — на месте надписи снова «Задать частоту», кнопка «Связались» пропала.

Группы. Если база заполнялась до появления групп, выполните сначала `pnpm db:migrate`: появятся три пустые группы. Тестовые контакты раскладываются по группам командой `pnpm db:seed` только на пустой базе, поэтому ниже группы вы расставляете сами.

13. Нажмите «Группы» на главной — видны «Друзья», «Коллеги», «Семья» и число контактов в каждой. Нажмите «Создать группу», впишите «Теннис» и нажмите «Создать» — группа встала по алфавиту после «Семья». Создайте «теннис» ещё раз — ошибка «Группа «Теннис» уже есть». «Отмена» закрывает поле.
14. Нажмите «Переименовать» у «Теннис», впишите «Большой теннис» и нажмите «Сохранить» — новое название сразу в списке. «Отмена» оставляет прежнее название.
15. Откройте карточку любого контакта. Рядом с частотой — кнопка «Добавить в группу». Нажмите её и отметьте «Друзья» — в шапке сразу появилась группа «Друзья», список остался открытым. Отметьте ещё «Большой теннис» — обе группы видны по алфавиту. Обновите страницу (F5) — группы на месте. Снимите отметки — группы пропадают, на их месте снова «Добавить в группу».
16. В списке групп впишите «Бег» и выберите «Создать группу «Бег»» — группа сразу в шапке карточки и на странице «Группы». Впишите «друзья» — предлагается существующая «Друзья», пункта «Создать» нет.
17. Нажмите «Изменить» — в поле «Группы» стоят группы контакта. Уберите одну, впишите «Аналитики», выберите «Создать группу «Аналитики»» и закройте форму крестиком, не сохраняя: в карточке всё как было, а на странице «Группы» нет «Аналитики». Повторите и нажмите «Сохранить» — группа появилась, и контакт в ней. Такое же поле есть в форме «Добавить контакт».
18. На главной в строке контакта под именем видны его группы. Выберите справа от поиска «Друзья» — остались только люди этой группы, сверху «Найдено: N контактов из 1 000», в адресе есть `?group=`. Впишите часть имени — фильтр и поиск работают вместе. Обновите страницу (F5) или откройте адрес в другом браузере — выбрана та же группа. «Все группы» возвращает весь список. Блок «Пора связаться» при выборе группы не меняется.
19. На странице «Группы» нажмите на название любой группы — главная откроется с этим фильтром. Выберите группу без людей — надпись «В группе «…» пока никого нет».
20. Нажмите «Удалить» у «Бег»: вопрос с числом контактов; «Отмена» ничего не удаляет, «Удалить» удаляет группу с сообщением «Группа удалена», контакты и заметки остаются.

## База данных (PostgreSQL в Docker)

Проверить, что база работает:

```
docker compose ps
```

В колонке `STATUS` у `db` должно быть `healthy`.

Остановить базу: `docker compose stop`. Данные хранятся в томе Docker `personal-crm_pgdata` и при остановке не пропадают.

Данные лежат в Docker, а не в папке проекта. Имя `personal-crm` закреплено в `compose.yaml` (строка `name: personal-crm`), поэтому папку проекта можно переносить и переименовывать — база останется той же. Эту строку не меняйте: иначе Docker создаст новую пустую базу, а контакты останутся в старой.

Удалить базу вместе со всеми данными: `docker compose down -v` — это необратимо.

Приложение подключается к базе по строке `DATABASE_URL` из `.env`.

## Выкатка на сервер

Версия на сервере: https://app.personalcrm.site. Жива ли она — видно на https://app.personalcrm.site/health: ответ `{"status":"ok","version":"<SHA коммита>"}`.

### Как выкатить новую версию

1. Закоммитьте изменения и отправьте их в ветку `main`: `git push`.
2. Больше ничего делать не нужно. GitHub Actions (вкладка **Actions** в репозитории, workflow **Deploy**) сам соберёт образ, положит его в GHCR с тегом — SHA коммита — и выкатит на сервер. Обычно это 3–4 минуты.
3. Проверьте: откройте https://app.personalcrm.site/health — в `version` должен быть SHA вашего коммита (его показывает команда `git rev-parse HEAD`).

Если отправить несколько коммитов подряд, выкатки пойдут по очереди.

### Что происходит при выкатке

1. GitHub собирает Docker-образ приложения и кладёт его в GHCR: `ghcr.io/artemjewpetya-lab/personal-crm:<SHA>`.
2. Копирует на сервер файлы из папки `deploy/` и запускает там `deploy.sh`, который:
   - скачивает новый образ;
   - запускает базу, если она не запущена;
   - применяет миграции отдельным разовым контейнером из нового образа. Упали миграции — новая версия не запускается, продолжает работать прежняя;
   - запускает новую версию;
   - smoke-проверка: ждёт до минуты, пока `/health` ответит 200 именно от новой версии;
   - удаляет старые образы приложения, оставляет только текущий и предыдущий.

### Если выкатка упала

Workflow станет красным, GitHub пришлёт письмо. Что случилось — в логе: **Actions → последний запуск Deploy → Deploy to the server → Run deploy/ci-deploy.sh**.

- **Упала сборка** (красный шаг Build and push image) — на сервере ничего не менялось.
- **Упали миграции** (`MIGRATIONS FAILED`) — новая версия не запускалась, работает прежняя.
- **Упал smoke** (`SMOKE TEST FAILED`) — новая версия запущена, но не отвечает. Сам ничего не откатывается. В конце лога напечатана команда отката на последнюю версию, которая прошла проверку.

### Откат вручную

Откат запускаете только вы. Образ предыдущей версии хранится на сервере, поэтому откат занимает меньше минуты:

```
ssh crm
sudo -u deploy bash /opt/personal-crm/deploy.sh "$(sudo cat /opt/personal-crm/state/previous_tag)"
```

Это вернёт версию, которая работала до последней удачной выкатки. Если упал smoke — используйте команду из лога.

Откат меняет только код: изменения структуры базы (миграции) он не отменяет.

### Где что лежит

- `Dockerfile` — как собирается образ.
- `.github/workflows/deploy.yml` — запуск выкатки на каждый push в `main`.
- `deploy/` — скрипты выкатки и состав сервисов на сервере (`compose.yaml`: приложение и база PostgreSQL).
- На сервере — папка `/opt/personal-crm` пользователя `deploy`: `compose.yaml` и `deploy.sh` (обновляются при каждой выкатке), `.env` с паролем базы, `state/` — какая версия текущая и какая предыдущая. Данные базы — в томе Docker `prod_pgdata`.
- nginx — `/etc/nginx/sites-available/personalcrm.conf`: запросы к app.personalcrm.site передаются приложению на `127.0.0.1:3000`.
- GitHub → **Settings → Secrets and variables → Actions**: секрет `DEPLOY_SSH_KEY` (ключ, которым GitHub заходит на сервер) и переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS`.

### `.env` на сервере

Файл `/opt/personal-crm/.env`, права 600 — читать его может только владелец (с другими правами выкатка остановится с ошибкой). Строки:

```
POSTGRES_USER=crm
POSTGRES_DB=crm
POSTGRES_PASSWORD=<случайный пароль: только латинские буквы и цифры>
```

### Логи приложения на сервере

```
ssh crm
sudo docker logs --tail 100 prod-app-1
```

## Требования к фичам: OpenSpec

Новые фичи описываются в OpenSpec ([openspec.dev](https://openspec.dev)): сначала требования и план, потом код. Тексты требований пишутся на русском.

- `openspec/specs/` — действующие требования к приложению.
- `openspec/changes/` — фичи в работе: у каждой своя папка с описанием (`proposal.md`), требованиями (`specs/`), техническим решением (`design.md`) и списком задач (`tasks.md`). Готовые фичи переезжают в `openspec/changes/archive/`.
- `openspec/config.yaml` — что OpenSpec сообщает агенту о проекте: язык текстов, где лежит идея продукта, правила работы.

Команды в Claude Code:

| Команда | Что делает |
| --- | --- |
| `/opsx:explore` | Обсудить идею, ничего не меняя |
| `/opsx:propose <имя>` | Описать фичу: требования, решение и задачи |
| `/opsx:update` | Поправить описание фичи |
| `/opsx:apply` | Сделать фичу по списку задач |
| `/opsx:sync` | Перенести требования фичи в `openspec/specs/`, не закрывая её |
| `/opsx:archive` | Закрыть готовую фичу: требования переходят в `openspec/specs/` |

После обновления OpenSpec (`npm install -g @fission-ai/openspec@latest`) выполните в папке проекта `openspec update` — он обновит команды в `.claude/`.

## Автотесты серверной части

`pnpm test` запускает тесты на Vitest: они проверяют запросы к базе и действия сервера (сохранение, поиск, группы и так далее). Экраны они не открывают — их проверяют руками и `pnpm test:e2e`.

- Нужна запущенная база: `docker compose up -d`. Без неё тесты остановятся с сообщением «Запустите базу: docker compose up -d».
- Тесты работают с отдельной базой `<имя вашей базы>_test` в том же Postgres. Перед каждым запуском она создаётся заново, между тестами очищается. Рабочая база и контакты в ней не затрагиваются; строки в `.env` для этого не нужны.
- Проверки вида «база недоступна» настоящие: приложение направляется на порт, где ничего нет, и тест убеждается, что соединения действительно нет.

## Автоматическая проверка сценария

`pnpm test:e2e` открывает приложение в Edge, добавляет контакт, находит его, пишет заметку, обновляет страницу, а потом открывает тот же адрес в Chrome и сверяет данные. Используются браузеры, уже установленные на компьютере, — в отдельном временном профиле, ваши вкладки и данные не затрагиваются. Созданный тестом контакт в конце удаляется из базы. Если приложение не запущено, тест сам запустит `pnpm dev`.

Там же проверяется частота общения и «Пора связаться» (`e2e/keep-in-touch.spec.ts`): частота в форме и карточке, смена частоты кнопкой в карточке и «Задать частоту»; от какого момента считается срок; порядок в блоке, текст строки и число дней («1 день», «2 дня», «5 дней», «Пора сегодня»); «Показать всех»; скрытие блока при поиске; кнопка «Связались» — из блока и из карточки, двойное нажатие и обрыв связи; «Отменить» — из блока и из карточки, через 10 секунд её нет, обрыв связи; уход контакта из блока после заметки. Тест сам создаёт контакты с датами в 1990-х годах (чтобы они были самыми просроченными в любой базе) и удаляет их после себя. Запустить только его: `pnpm test:e2e e2e/keep-in-touch.spec.ts`.

## Про символ «#» в пути к папке

Раньше проект лежал в папке `# Онлайн курсы`, а символ `#` в пути мешает некоторым инструментам. Сейчас папка называется `00 Онлайн курсы`, и проблем нет. Если когда-нибудь снова положить проект в папку с `#` в названии:

- Tailwind CSS (оформление интерфейса) по-прежнему соберётся: на этот случай оставлен патч `patches/@tailwindcss__node@4.3.3.patch`, он применяется автоматически при `pnpm install` и в обычной папке ни на что не влияет. При обновлении Tailwind патч, возможно, придётся обновить или убрать.
- В режиме `pnpm dev` в окне сервера может появляться ошибка `Could not validate instant ... Could not find the module ... in the React Client Manifest`. Это сбой внутренней проверки Next.js из-за `#`, на работу приложения он не влияет, а в `pnpm start` его нет.
