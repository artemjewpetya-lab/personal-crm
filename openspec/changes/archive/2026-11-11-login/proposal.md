# Proposal

## Why

Приложением хотят пользоваться друзья, а сейчас все, кто открыл адрес, видят одни и те же контакты. Нужно, чтобы каждый входил под своей почтой, вёл свои контакты, заметки и группы и не видел чужих. Требования владельца - `specs/02-пользователи-вход.md`.

## What Changes

- **BREAKING** Без входа приложение не открывается: любая страница ведёт на страницу входа. Открыты только сама страница входа, переход по ссылке из письма и служебная проверка `/health`.
- Вход только по ссылке из письма, без паролей. Первый вход и есть регистрация: отдельной формы нет, имя не спрашиваем.
  - Страница входа: поле почты и кнопка «Получить ссылку». После отправки - «Ссылка для входа отправлена на <почта>», одинаково для новой и знакомой почты.
  - Почта: пробелы по краям убираются, большие и маленькие буквы не различаются. Неверный адрес - ошибка под полем «Проверьте адрес почты», письмо не уходит. Сервер проверяет так же, даже если запрос пришёл не из формы.
  - Ссылка работает один раз и 15 минут; новая ссылка отменяет старые. Старая или использованная ссылка - «Ссылка устарела, запросите новую» и кнопка на страницу входа.
  - Не больше 3 писем на одну почту за 10 минут, дальше - «Слишком часто, попробуйте через несколько минут».
  - С одного устройства - вход не больше чем на 5 разных адресов за час, дальше - «С этого устройства запрашивали вход на слишком много адресов. Попробуйте позже.» Это защищает от рассылки писем по чужим адресам. Устройство узнаётся по адресу в интернете: одна домашняя сеть - одно устройство (решение владельца, 2026-11-10).
  - Письмо не удалось отправить - «Не удалось отправить письмо. Попробуйте ещё раз через пару минут.»
  - Вход держится 30 дней с последнего захода на этом устройстве, можно сидеть с нескольких устройств сразу.
  - В шапке - почта пользователя и кнопка «Выйти». Выход - только на этом устройстве.
- Письмо: отправитель «Личная CRM» <noreply@mail.personalcrm.site>, тема «Вход в Личную CRM», кнопка «Войти», срок 15 минут и «Если вы не запрашивали вход - просто проигнорируйте письмо».
- Куда уходят письма, решают настройки, а не код - одна сборка работает везде:
  - на компьютере владельца и в автотестах (в том числе на GitHub) - в почтовую заглушку Mailpit: письма никуда не уходят, их видно на её странице в браузере, войти можно под любым адресом;
  - на сервере - настоящие письма через сервис Resend.
  - Письма везде отправляет одна библиотека Nodemailer.
- У каждого контакта и группы появляется владелец; заметки принадлежат владельцу контакта. Пользователь видит и меняет только своё: список, поиск, карточку, заметки, группы, фильтр по группе, «Пора связаться». Чужое не открывается ни в интерфейсе, ни прямым запросом к серверу; чужой контакт по прямой ссылке выглядит как несуществующий («Такого контакта нет»).
- Группы у каждого свои: у двух пользователей может быть по группе «Друзья». Каждый новый пользователь сразу получает свои пустые «Семья», «Друзья», «Коллеги».
- Новый пользователь видит пустой список с подсказкой, которая уже есть в приложении: «Пока нет ни одного контакта» и «Нажмите «Добавить контакт», чтобы записать первого человека».
- Всё, что уже есть в базе (контакты, заметки, группы), становится данными владельца - пользователя с почтой из настройки `OWNER_EMAIL`. Демо-данные (`pnpm db:seed`) тоже создаются у него. Ни одна запись не теряется.
- Откат после выкатки входа - только вместе: база из копии, снятой перед выкаткой, и прошлая версия приложения. Порядок - в README.
- Автотесты: новый автотест входа в браузере (два пользователя, A и B). Автотест главного сценария из `specs/01-продуктовая-идея.md` остаётся отдельным и перед сценарием входит под владельцем, в том числе во втором браузере.

## Capabilities

### New Capabilities

- `sign-in`: вход по ссылке из письма - страница входа, проверка почты, письмо и его содержимое, срок и одноразовость ссылки, лимиты писем на почту и на устройство, сбой отправки, срок входа, выход, почта в шапке, закрытость приложения без входа, куда уходят письма в разных окружениях.
- `data-ownership`: чьи данные - владелец у контактов, заметок и групп, «только своё» во всех экранах и запросах к серверу, чужой контакт как несуществующий, пустое начало нового пользователя, передача уже существующих данных и демо-данных владельцу.

### Modified Capabilities

- `contact-groups`: «Готовые группы» - три группы теперь у каждого пользователя: уже существующие переходят владельцу, новый пользователь получает свои при первом входе. «Название группы» - одинаковые названия запрещены только внутри групп одного пользователя.

Требования `keep-in-touch` не меняются: блок работает как раньше, но на своих контактах - это общее правило из `data-ownership`.

## Impact

- База данных: новые таблицы пользователей, входов на устройствах, одноразовых ссылок и журнала отправленных писем; у контактов и групп - столбец владельца. Миграция **меняет существующие данные** (назначает им владельца) - до merge показать её владельцу проекта.
- Код: все запросы и серверные действия контактов, заметок и групп получают текущего пользователя; новые страница входа, страница «ссылка устарела», шапка с почтой и «Выйти», проверка входа перед каждой страницей.
- Новые библиотеки (утверждены в `specs/02-пользователи-вход.md`): Better Auth - вход по ссылке; Nodemailer - отправка писем. Новые сервисы: Mailpit (заглушка в Docker локально и в CI), Resend (настоящие письма на сервере).
- Настройки (`.env` локально и на сервере, переменные в CI): секрет и адрес для Better Auth, почтовый сервер (SMTP), адрес отправителя, `OWNER_EMAIL`. Строки в `.env` и `.env.example` добавляет владелец проекта - агенту эти файлы недоступны.
- nginx на сервере должен передавать приложению настоящий адрес устройства (заголовок `X-Real-IP` в нашем блоке `app.personalcrm.site`), иначе лимит на устройство сочтёт всех одним устройством. Проверить и при необходимости добавить строку - до выкатки.
- Выкатка: `deploy/compose.yaml` передаёт приложению и миграциям новые настройки; без них выкатка останавливается до бэкапа, работает прошлая версия. До первой выкатки владельцу нужно: завести Resend, подтвердить домен `mail.personalcrm.site` записями DNS, положить ключ и остальные строки в `.env` на сервере.
- CI: Mailpit рядом с базой в проверке «Tests», новые переменные.
- Автотесты: все существующие e2e входят под владельцем; тестовые контакты, которые e2e создают прямо в базе, получают владельца.
- `README.md`: вход, Mailpit, новые настройки, проверка руками двух пользователей, порядок отката.
