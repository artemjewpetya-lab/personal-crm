# sign-in Specification

## Purpose

Пускает в приложение только того, кто подтвердил свою почту ссылкой из письма, без паролей, и держит его внутри на этом устройстве, пока он не выйдет или долго не заходит. Первый вход по ссылке и есть регистрация.

## Requirements

### Requirement: Без входа приложение закрыто
Без входа приложение SHALL показывать только страницу входа: любая страница приложения, в том числе открытая по прямой ссылке, ведёт на неё. Сервер не отдаёт и не меняет данные по запросу без входа. Без входа открыты только страница входа, переход по ссылке из письма, страница «Ссылка устарела» и служебная проверка `/health`, по которой выкатка понимает, что приложение живо.

#### Scenario: Открыл приложение без входа
- **GIVEN** пользователь не вошёл
- **WHEN** он открывает главную
- **THEN** видна страница входа: заголовок «Вход в Личную CRM», поле «Почта» и кнопка «Получить ссылку»

#### Scenario: Прямая ссылка без входа
- **GIVEN** пользователь не вошёл
- **WHEN** он открывает адрес карточки контакта или страницы «Группы»
- **THEN** видна страница входа, данных контакта и групп на ней нет

#### Scenario: Запрос к серверу без входа
- **GIVEN** запрос пришёл без входа
- **WHEN** он просит добавить, изменить или удалить контакт, заметку или группу
- **THEN** ничего не меняется и данные не отдаются

#### Scenario: Проверка /health
- **GIVEN** пользователь не вошёл
- **WHEN** открывается `/health`
- **THEN** ответ - как раньше: приложение живо и видит базу

### Requirement: Запрос ссылки для входа
На странице входа пользователь SHALL вписать почту и нажать «Получить ссылку». После отправки видно «Ссылка для входа отправлена на <почта>», и на эту почту уходит письмо со ссылкой. Ответ одинаковый для почты, под которой уже входили, и для новой: по нему нельзя узнать, есть ли такой пользователь. Отдельной регистрации нет, имя не спрашивается: первый вход по ссылке создаёт пользователя. Другой ответ бывает только при неверном адресе, сработавшем лимите или сбое отправки.

#### Scenario: Ссылка отправлена
- **WHEN** пользователь вписывает «anna@example.com» и нажимает «Получить ссылку»
- **THEN** видно «Ссылка для входа отправлена на anna@example.com»
- **AND** на anna@example.com приходит письмо для входа

#### Scenario: Новая и знакомая почта
- **GIVEN** под anna@example.com уже входили, а под boris@example.com - ни разу
- **WHEN** пользователь по очереди запрашивает ссылку для обеих почт
- **THEN** в обоих случаях одинаковое сообщение «Ссылка для входа отправлена на <почта>», и оба письма приходят

#### Scenario: Первый вход - регистрация
- **GIVEN** под boris@example.com ни разу не входили
- **WHEN** пользователь открывает ссылку из письма на boris@example.com
- **THEN** он сразу внутри приложения, без формы регистрации и без вопроса об имени

### Requirement: Почта без пробелов и без учёта регистра
Почту SHALL сохранять и сравнивать без пробелов в начале и в конце и без различия больших и маленьких букв. «Anna@Example.com» и «anna@example.com» - одна почта и один пользователь. В сообщении после отправки и в шапке почта показывается маленькими буквами, без пробелов по краям.

#### Scenario: Пробелы и большие буквы
- **WHEN** пользователь вписывает « Anna@Example.COM » и нажимает «Получить ссылку»
- **THEN** видно «Ссылка для входа отправлена на anna@example.com», письмо приходит на anna@example.com

#### Scenario: Одна почта - один пользователь
- **GIVEN** пользователь вошёл как anna@example.com и добавил контакт «Вера»
- **WHEN** он выходит и входит по ссылке, запрошенной для «ANNA@example.com»
- **THEN** он видит свой контакт «Вера»

### Requirement: Неверный адрес почты
Если почта пустая или не похожа на адрес почты, под полем SHALL появляться ошибка «Проверьте адрес почты», и письмо не уходит. Сервер проверяет почту по тем же правилам и тогда, когда запрос пришёл не из формы: такой запрос тоже отклоняется с той же ошибкой, и письмо не уходит.

#### Scenario: Неверный адрес в форме
- **WHEN** пользователь вписывает «anna@» и нажимает «Получить ссылку»
- **THEN** под полем ошибка «Проверьте адрес почты», письма нет

#### Scenario: Пустое поле
- **WHEN** пользователь нажимает «Получить ссылку», не вписав почту
- **THEN** под полем ошибка «Проверьте адрес почты», письма нет

#### Scenario: Неверный адрес не из формы
- **WHEN** запрос ссылки с адресом «anna@» приходит на сервер в обход формы
- **THEN** сервер отказывает с ошибкой «Проверьте адрес почты», письма нет

### Requirement: Не больше 3 писем на почту за 10 минут
На одну почту SHALL уходить не больше 3 писем для входа за любые 10 минут. Четвёртый запрос в эти 10 минут получает ошибку «Слишком часто, попробуйте через несколько минут», письмо не уходит, новая ссылка не создаётся, прежние ссылки продолжают работать. Лимит считается для каждой почты отдельно и действует и на запросы не из формы.

#### Scenario: Четвёртый запрос за 10 минут
- **GIVEN** за последние 10 минут на anna@example.com ушло 3 письма
- **WHEN** пользователь снова запрашивает ссылку для anna@example.com
- **THEN** видно «Слишком часто, попробуйте через несколько минут», четвёртого письма нет

#### Scenario: Через 10 минут снова можно
- **GIVEN** на anna@example.com ушло 3 письма, первое из них - больше 10 минут назад
- **WHEN** пользователь запрашивает ссылку для anna@example.com
- **THEN** видно «Ссылка для входа отправлена на anna@example.com», письмо приходит

#### Scenario: Другая почта не ждёт
- **GIVEN** для anna@example.com лимит исчерпан
- **WHEN** пользователь запрашивает ссылку для boris@example.com
- **THEN** письмо на boris@example.com уходит

#### Scenario: Та же почта, написанная иначе
- **GIVEN** за последние 10 минут на anna@example.com ушло 3 письма
- **WHEN** приходит запрос для «Anna@Example.com»
- **THEN** видно «Слишком часто, попробуйте через несколько минут», письма нет

### Requirement: Не больше 5 разных адресов с одного устройства за час
С одного устройства SHALL можно запросить вход не больше чем для 5 разных адресов почты за любой час. Устройство узнаётся по адресу в интернете, с которого пришёл запрос, поэтому все в одной домашней сети считаются одним устройством. Запрос для шестого адреса получает «С этого устройства запрашивали вход на слишком много адресов. Попробуйте позже.», письмо не уходит, ссылка не создаётся. Адреса из этих пяти запрашивать можно. Действует и на запросы не из формы.

#### Scenario: Шестой адрес за час
- **GIVEN** с этого устройства за последний час запрашивали вход для 5 разных адресов
- **WHEN** с него запрашивают вход для шестого адреса
- **THEN** видно «С этого устройства запрашивали вход на слишком много адресов. Попробуйте позже.», письма на шестой адрес нет

#### Scenario: Адрес из этих пяти
- **GIVEN** с этого устройства за последний час запрашивали вход для 5 разных адресов, среди них anna@example.com, и на него ушло одно письмо
- **WHEN** с него снова запрашивают вход для «Anna@Example.com»
- **THEN** видно «Ссылка для входа отправлена на anna@example.com», письмо приходит

#### Scenario: Через час снова можно
- **GIVEN** с этого устройства запрашивали вход для 5 разных адресов, для первого из них - больше часа назад
- **WHEN** с него запрашивают вход для нового адреса
- **THEN** видно «Ссылка для входа отправлена на <почта>», письмо приходит

#### Scenario: Другое устройство не ждёт
- **GIVEN** на первом устройстве лимит адресов исчерпан
- **WHEN** со второго устройства, из другой сети, запрашивают вход для нового адреса
- **THEN** письмо уходит

#### Scenario: Лимит устройства не из формы
- **GIVEN** с этого устройства за последний час запрашивали вход для 5 разных адресов
- **WHEN** запрос для шестого адреса приходит с него на сервер в обход формы
- **THEN** сервер отказывает с «С этого устройства запрашивали вход на слишком много адресов. Попробуйте позже.», письма нет

### Requirement: Письмо не удалось отправить
Если письмо для входа не удалось отправить, например почтовый сервер недоступен, под полем SHALL появляться «Не удалось отправить письмо. Попробуйте ещё раз через пару минут.». Сообщения «Ссылка для входа отправлена» нет, прежние ссылки для этой почты продолжают работать, а неудачная попытка не засчитывается ни в один лимит.

#### Scenario: Почтовый сервер недоступен
- **GIVEN** у anna@example.com есть действующая ссылка из прошлого письма, а почтовый сервер недоступен
- **WHEN** пользователь запрашивает ссылку для anna@example.com
- **THEN** под полем «Не удалось отправить письмо. Попробуйте ещё раз через пару минут.»
- **AND** ссылка из прошлого письма по-прежнему впускает в приложение, а в лимиты эта попытка не засчиталась

### Requirement: Письмо для входа
Письмо для входа SHALL приходить от отправителя «Личная CRM» с темой «Вход в Личную CRM». В письме - кнопка «Войти» со ссылкой для входа, сказано, что ссылка работает 15 минут, и строка «Если вы не запрашивали вход - просто проигнорируйте письмо». На сервере адрес отправителя - noreply@mail.personalcrm.site.

#### Scenario: Что в письме
- **WHEN** пользователь запросил ссылку для anna@example.com
- **THEN** в письме отправитель «Личная CRM», тема «Вход в Личную CRM», кнопка «Войти», срок 15 минут и строка «Если вы не запрашивали вход - просто проигнорируйте письмо»

#### Scenario: Отправитель на сервере
- **WHEN** пользователь запрашивает ссылку в версии на сервере
- **THEN** письмо приходит в настоящий почтовый ящик от «Личная CRM» <noreply@mail.personalcrm.site>

### Requirement: Вход по ссылке из письма
Ссылка из письма SHALL впускать в приложение один раз и только 15 минут с момента отправки; после входа видна главная со своими контактами. Новая ссылка для той же почты отменяет все прежние. Использованная, просроченная, отменённая или испорченная ссылка ведёт на страницу «Ссылка устарела, запросите новую» с кнопкой «Запросить новую ссылку», которая открывает страницу входа.

#### Scenario: Вошёл по ссылке
- **WHEN** пользователь открывает ссылку из письма в течение 15 минут
- **THEN** он внутри: видна главная с его контактами, в шапке его почта

#### Scenario: Ссылку открыли второй раз
- **GIVEN** пользователь уже вошёл по ссылке
- **WHEN** он открывает ту же ссылку ещё раз, в том числе в другом браузере
- **THEN** видно «Ссылка устарела, запросите новую» и кнопка «Запросить новую ссылку»

#### Scenario: Прошло больше 15 минут
- **GIVEN** письмо пришло больше 15 минут назад
- **WHEN** пользователь открывает ссылку из него
- **THEN** видно «Ссылка устарела, запросите новую», вход не происходит

#### Scenario: Запросил новую ссылку
- **GIVEN** пользователь получил два письма для одной почты, одно за другим
- **WHEN** он открывает ссылку из первого письма
- **THEN** видно «Ссылка устарела, запросите новую»
- **AND** ссылка из второго письма впускает в приложение

#### Scenario: Испорченная ссылка
- **WHEN** пользователь открывает ссылку для входа с изменённым или обрезанным кодом
- **THEN** видно «Ссылка устарела, запросите новую», вход не происходит

#### Scenario: Кнопка на странице «Ссылка устарела»
- **WHEN** пользователь нажимает «Запросить новую ссылку»
- **THEN** открывается страница входа с пустым полем почты

### Requirement: Вход держится 30 дней
Вход SHALL держаться на устройстве 30 дней с последнего захода в приложение на этом устройстве: каждый заход продлевает срок. Если 30 дней не заходить, приложение снова показывает страницу входа. Можно быть в приложении с нескольких устройств и браузеров сразу.

#### Scenario: Заходит регулярно
- **GIVEN** пользователь вошёл и затем заходит в приложение раз в 20 дней
- **WHEN** он открывает приложение через 40 дней после входа по ссылке
- **THEN** он внутри, страницы входа нет

#### Scenario: Не заходил 30 дней
- **GIVEN** пользователь не открывал приложение на этом устройстве 30 дней
- **WHEN** он его открывает
- **THEN** видна страница входа

#### Scenario: Два устройства
- **WHEN** пользователь входит по ссылкам в двух разных браузерах
- **THEN** в обоих он внутри и видит одни и те же свои контакты

### Requirement: Почта в шапке и выход
Когда пользователь внутри, в шапке SHALL быть его почта и кнопка «Выйти». «Выйти» завершает вход только на этом устройстве и открывает страницу входа; на других устройствах пользователь остаётся внутри. На странице входа в шапке нет почты и кнопки «Выйти».

#### Scenario: Шапка
- **GIVEN** пользователь вошёл как anna@example.com
- **WHEN** он открывает любую страницу приложения
- **THEN** в шапке видны «anna@example.com» и кнопка «Выйти»

#### Scenario: Выйти
- **GIVEN** пользователь внутри
- **WHEN** он нажимает «Выйти»
- **THEN** видна страница входа
- **AND** кнопка «Назад» в браузере и обновление страницы тоже показывают страницу входа, а не контакты

#### Scenario: Выход только на этом устройстве
- **GIVEN** пользователь вошёл в двух браузерах
- **WHEN** он нажимает «Выйти» в первом
- **THEN** во втором он по-прежнему внутри

#### Scenario: Шапка на странице входа
- **GIVEN** пользователь не вошёл
- **WHEN** он открывает страницу входа
- **THEN** в шапке нет почты и кнопки «Выйти»

### Requirement: Куда уходят письма
Куда уходят письма, SHALL решать настройки, а не код: одна и та же сборка приложения работает и на компьютере владельца, и на сервере. На компьютере владельца и в автотестах, в том числе на GitHub, письма попадают в почтовую заглушку и никуда наружу не уходят; войти можно под любым адресом, ссылку берут из заглушки. На сервере уходят настоящие письма.

#### Scenario: Письмо на компьютере владельца
- **GIVEN** приложение запущено на компьютере владельца
- **WHEN** он запрашивает ссылку для придуманного адреса test-a@example.com
- **THEN** письмо видно на странице почтовой заглушки, наружу оно не ушло
- **AND** ссылка из него впускает в приложение как test-a@example.com

#### Scenario: Письмо в автотестах
- **WHEN** автотест запрашивает ссылку для входа
- **THEN** письмо попадает в почтовую заглушку, и автотест берёт ссылку оттуда; настоящих писем нет

#### Scenario: Письмо на сервере
- **WHEN** пользователь запрашивает ссылку в версии на сервере
- **THEN** письмо приходит в его настоящий почтовый ящик

#### Scenario: Та же сборка, другие настройки
- **GIVEN** одна и та же сборка приложения
- **WHEN** в настройках указан почтовый сервер заглушки или почтовый сервер для настоящих писем
- **THEN** письма уходят туда, куда указывают настройки, без изменения кода
